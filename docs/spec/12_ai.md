## 1. 目标与范围

### 1.1 分层

| 层 | 名称 | 本质 | 技术（✅ §20.1） | 频率 | 谁使用 | 本文件管什么 |
|---|---|---|---|---|---|---|
| L0 | 片段内战术 | 物理与概率 | 03 §4.9.1 的固定规则 | 每刻 | 双方 | 不管（03 C-10） |
| L1 | 条带条令 | 按条令行事 | 规则 + 效用 + 条带上的“通道评分” | 每条带步（5 min） | 双方 | **决策规则与 `DoctrineProfile`**；执行（移动、几何、时间）归 04 的 `StripDoctrineAi` 🟡 I-01 |
| L2 | 编组 AI `FormationAi` | 任务分解 | 效用 + 影响力图 + 比例分配 | 旅：每条带步；师：每 60 min | 双方（玩家的旅也由它自动分配到边） | 全部 |
| L3 | 作战 AI `OperationalAi` | 真正的决策 | HTN + 效用 + 影响力图 + 代理模型（可选 MCTS，阶段 2+） | 每 60 min | 仅 AI 国家 | 全部 |
| L4 | 国家 AI `CountryAi` | 采购、编制、战备、开战 | 效用 + 代理模型 | 每日（年度、月度门控） | 仅 AI 国家 | 全部（通过 11 的 `IStrategicActions`，和玩家同一接口） |
| — | 代理模型 `ProxyModel` | 快速估算胜算 | 离线训练的梯度提升树（GBDT） | 按需 | L2–L4、11 | 全部 |

### 1.2 阶段
- **阶段 0**：`DoctrineProfile` 与 L1 规则（试验场的条带对战需要）；`ProxyModel` 的训练数据生成规范与训练流水线（数据来自试验场）；`UtilityCurve`、`AiDecisionTrace`。
- **阶段 1（纳卡）**：L2、L3、L4 全部，只为亚美尼亚（ARM）和阿塞拜疆（AZE）两个可玩国家；外部大国的行为由 11 §4.10 的规则驱动，不用本文件的 L3/L4（🟡 I-21）。
- **阶段 2+**：MCTS 方案推演；玩家把战区委托给 AI；`FidelityTier.Proxy` 的远方战争日结算（§4.9）；AI 对玩家扩军的反应（§21-19 军备竞赛）；海军。

### 1.3 不包含
- 片段内部的选目标/移动（03）；条带上连的移动执行、行进时间、火力结算（04）；空中任务的飞行与交战（08）；后勤网络流和仓库分配（06 自带的“AI 定放哪里”）；领导层审批与政治规则（11）。
- **模拟里不嵌入 LLM**（✅ §20.2）。

```csharp
// 效用曲线：只允许分段线性（不用 Exp/Logistic，见 I-13），x 超出两端取端点值
public sealed class UtilityCurve {
    public double[] xs;    // 严格递增，长度 ≥ 2
    public double[] ys;    // 同长度，取值 [0,1]
    public double Eval(double x) {
        if (x <= xs[0]) return ys[0];
        for (int i = 1; i < xs.Length; i++)
            if (x <= xs[i]) return ys[i-1] + (ys[i]-ys[i-1]) * (x - xs[i-1]) / (xs[i] - xs[i-1]);
        return ys[^1];
    }
}

public sealed class Consideration {
    public string id;               // 例 "threat", "terrain_fit"
    public UtilityCurve curve;
    public double weight;           // ≥ 0
    public bool isVeto;             // true：curve 输出 0 时整个选项效用为 0（不参与加权）
}

// 选项评分：U = Π(veto) × Σ(w_i × c_i) / Σ(w_i)，取值 [0,1]
public readonly record struct ScoredOption(int optionKey, double utility, double[] considerationValues);

public enum AiLayer : int { None = 0, Doctrine = 1, Formation = 2, Operational = 3, Country = 4 }
```

### 4.0 执行时机与确定性总则

| 什么 | 阶段 | 频率 | 顺序 |
|---|---|---|---|
| 情报画面、影响力图重建 | 10 `AiDecision` 开头 | `n % 60 == 0` | 国家 `CountryId` 升序 |
| `CountryAi` | 10 | `n % 1440 == 0`（内部再按年/月门控） | `CountryId` 升序 |
| `OperationalAi` | 10 | `n % 60 == 0`，且（战争中或紧张度 ≥ `Crisis`） | `CountryId` 升序 |
| `FormationAi`（师） | 10 | `n % 60 == 0` | `FormationId` 升序 |

**总则**
1. 自上而下：同一刻内 国家 → 作战 → 师 → 旅。下级只按**已生效**的命令/任务行动（命令延迟由 09 计算，AI 命令和玩家命令走同一通道，✅ 00 §5.2）。
2. **不作弊**（🟡 I-07）：L2–L4 只读本国真值 + `AiIntelPicture`（05 的 `IntelEstimate`）+ 公开信息（地块控制权 `TileControl`、战争与紧张度状态、本国参与的 `EdgeBattle` 的存在与位置）。不得读取敌方单位真值。L1 只读 04 组装的 `StripSituationView`（其中敌方信息已按局部暴露度过滤）。
3. 不用真实时间预算；所有搜索的规模由**固定次数**限定（候选数、迭代数）。
4. 所有比较平局：先按规定主键，最后按实体 ID 升序（00 §6.4）。浮点效用比较“相等”定义为 `|a − b| ≤ 1e-12`，相等时按 ID。
5. 随机：只用于 §4.8 的轴线扰动，`Rng.For(RngDomain.Ai, entityKey, tick, salt)`；salt 表见 §5.6。
6. 所有 AI 产生的命令走 09 `SubmitOrder`（`source = Ai`）；战略层动作走 11 `IStrategicActions`。

### 4.1 通用构件

#### 4.1.1 效用计算
```csharp
double Utility(Consideration[] cs, double[] inputs, double[] outValues) {
    double sumW = 0, sum = 0;
    for (int i = 0; i < cs.Length; i++) {
        double c = cs[i].curve.Eval(inputs[i]); outValues[i] = c;
        if (cs[i].isVeto) { if (c <= 0) return 0; continue; }
        sum += cs[i].weight * c; sumW += cs[i].weight;
    }
    return sumW > 0 ? sum / sumW : 0;
}
```

#### 4.1.2 战斗力指数 CP（参考机步营 = 1.0）🟡 I-22
```text
自方营：CP(bn) = AmmoMod × [ 0.30 × pe/PE_ref + 0.25 × (alA + ahA)/AA_ref + 0.20 × ap/AP_ref
                             + 0.15 × sup/SUP_ref + 0.10 × oi/OI_ref ]
   pe, alA, ahA, ap, sup, oi = 03 BattalionSummary.capability 的 personnelEffective、antiLightArmor、antiHeavyArmor、
                               antiPersonnel、suppression、organicIndirect
   AmmoMod = min(1, ammoFraction / 0.3)       （与 03 §4.14.3 同形）
   *_ref = 参考营 RefBattalionTemplate（默认 "ref_mech_inf_bn"，由 14 指定一个本剧本的典型机步营模板）满编、
           练度 0.5 时的同名分量；加载剧本时计算一次
敌方估计：cpEstimate = VE_est × CpPerVe[typeGuess]           （L2+；VE = 05 的 estVehicleEquivalent）
          L1：cpEstimate = PriorCpL1                           （“有一个营级目标”）
          L5：再 × estStrengthFraction
          confidence = useIntelAgeDiscount ? max(MinIntelConfidence, 1 − ageH / IntelStaleH) : 1
          cpErrorFrac = ErrByLevel[level]
   ageH = (now − ExposureRecord.lastObservedTime) / 3 600 000
   CpPerVe[type]：加载剧本时 = 该类型参考营的 CP ÷ 其车辆当量（14 给每类一个参考模板；缺省 0.04/VE）
```
- 已识破的假目标（`isKnownDecoy`）不计入；未识破的计入（AI 可以被骗，✅ §10.5“可能被欺骗”）。

#### 4.1.3 影响力图（每国每小时）
```text
对战区每个地块 t（H3 升序）：
  FriendlyCp[t] = Σ CP(本国营，归属 t)
  EnemyCp[t]    = Σ cpEstimate × confidence（情报画面中 tile == t 的敌方）
  Threat[t]     = Σ_u EnemyCp[u] × InfluenceDecay^hops(u,t)     对 hops ≤ InfluenceMaxHops
  Support[t]    = Σ_u FriendlyCp[u] × InfluenceDecay^hops(u,t)  同上
  Vulnerability[t] = Threat[t] − Support[t]
  Value[t]      = 14 的 keyTile 价值 + Σ 本国节点价值（06：Depot 3，ForwardHub 2，Airbase 3，Factory 2，ImportGateway 3）
                  + 2 × urbanFraction(t)（10）+ (t 是首都 ? 10 : 0)
  Frontline[t]  = (controller(t) == 本国 且 存在邻格 u：controller(u) 为敌国 或 EnemyCp[u] > 0) ? 1 : 0
hops：在陆地邻接图上的 BFS 距离；BFS 队列按 H3Index 升序入队；超出战区的地块不计。
```

#### 4.1.4 情报不确定性的三档
对任何“以敌方估计为输入”的代理模型调用，同时算三档：`low`（敌 CP × (1 − cpErrorFrac)）、`mid`、`high`（× (1 + cpErrorFrac)），得到 `(P_low, P_mid, P_high)`。决策用 `mid`；置信区间半宽 = `(P_low − P_high) / 2`（攻方视角 P_low ≥ P_high）。这让“侦察越好区间越窄”自然出现。

#### 4.3.2 分解 `Decompose(formation, task)`（命令生效时调用一次；返回营级子命令）
```text
营分类（01 InferBranch / 05 typeGuess 的自方真值）：
  机动营 M（坦克、机步、摩步、步兵、侦察）；支援营 S（炮兵、防空、工兵、后勤、指挥部、电子战）

Defend(tiles)：
  1. 地块权重 w_t = max(ThreatFloor, Threat[t]) × (1 + Value[t] / ValueNorm)
  2. 机动营按“先每格 1 个，余数按最大余数法”分到各格（§4.3.4 的 Allocate 函数，格按 w 降序、平局 H3 小者）
  3. 每格的机动营挑选：按 CP 降序依次给 w 最大的格（平局 ID 小者）；已在该格的营优先留下（+RetaskPenalty 的反向奖励）
  4. 支援营：去机动营最多的格；炮兵若到所有被分配格边中点的距离均 ≤ 射程 × 0.8 则留原地
Attack(T)：
  1. 攻击边 e = 编组所在的己方地块与 T 的公共边中，Utility_edge 最高者：
       U_edge = 0.5 × P_mid(攻 = 可用机动营, 防 = T 内敌估计, 边地形) + 0.3 × openFrac(e) × armorShare + 0.2 × (1 − Threat[from]/ThreatNorm)
     （armorShare = 机动营平均 protection；P_mid 来自 §4.6 EstimateEdge）
  2. 留守：出发格除 e 外，Threat ≥ CoverThreatMin 的每条边留 1 个机动营（CP 最低且合适者）
  3. 预备：机动营数 ≥ 4 时留 round(M × brigadeReserveBattalionShare)（至少 1）在出发格作为 TileReserve
  4. 其余机动营：Move(path = [T])，第一步穿过 e（09 寻路时把 e 指定为必经边）
  5. 炮兵：若出发格中心到 e 中点距离 > 射程 × 0.8，则移动到与 e 相邻、距离满足的己方格；否则留下
```

#### 4.3.3 地块内防守分配（旅，每条带步）
```text
对编组的每个所在地块 t（H3 升序），机动营集合 M_t（排除：在 EdgeBattle 中、过边中、有生效中的 Move 命令要离开 t 的）：
  对 t 的每条边 e（EdgeId 升序）：
     neighbor = e 对面的格
     threat_e = Σ_{敌估计 in neighbor} cpEstimate × confidence + EdgeInfluenceShare × Threat[neighbor]
              + (e 上有本国参与的活跃 EdgeBattle ? BattleThreatBonus × 战斗中敌方已知 CP : 0)
     若 neighbor 为本国控制且无敌情：threat_e = 0
  R = (|M_t| ≥ 3) ? 1 : 0                    // 地块预备
  A = |M_t| − R
  covered = threat_e ≥ CoverThreatMin 的边，按 threat 降序
  quotas = Allocate(A, covered.threats)      // §4.3.4
  逐边匹配营（边按 threat 降序）：对每个名额选 suitability 最大的未分配营
     suitability(bn, e) = CP(bn) × terrainFit(bn, e) − (bn 当前分配 ≠ e ? RetaskPenalty × CP(bn) : 0)
     terrainFit = 1 + 0.4 × (openFrac(e) − 0.5) × (2 × armorness(bn) − 1)      // armorness = protection ∈ [0,1]
  余下营 → TileReserve；无 covered 边时全部 TileReserve
  候选方案总效用 U_new = Σ_assigned suitability × threat_e / Σthreat（无威胁时 = 0）
采用规则（滞回）：
  若 U_new ≥ U_cur × (1 + RetaskGainMin) 或 存在紧急情况 → 对每个分配变化的营：
       其 tick − lastChangeTick ≥ MinDwellMin（紧急时忽略）才改；
       pendingEdge/Role = 新值；pendingEffectiveTick = ceil((now + 09.PreviewDelay(Reactive, bn).totalMs)/60000)
  紧急情况 = 本步有 EdgeBattle 在 t 的某边开始而该边无分配营；或收到 R6 的接替请求；或分配边上的防守营平均战斗力 < EmergencyCombatStrength
到期生效（每步开头）：pendingEffectiveTick ≤ n → edge/role = pending；lastChangeTick = n；
  若新 edge 上有本国参与的活跃 EdgeBattle → 调 04.JoinBattle(battleId, bn)（营作为增援进入条带预备位置）
```
- **为什么要滞回和驻留**：防止营在两条边之间来回跑（✅ “稳定、合理”）。界面显示被抑制的调整及原因（§2.2）。

#### 4.3.4 名额分配函数（确定性最大余数法）
```text
Allocate(A, threats[0..k−1])  // threats 已按降序（平局 EdgeId 小者）
  q = new int[k]
  for i in 0..min(A,k)−1: q[i] = 1                 // 先每边 1 个（威胁大的优先）
  rem = A − min(A,k)
  if rem > 0 and Σthreats > 0:
     share_i = rem × threats[i] / Σthreats
     q[i] += floor(share_i)
     余下 rem − Σfloor 个名额按 (share_i − floor(share_i)) 降序（平局 i 小者）各加 1
  return q
```

#### 4.6.3 推理（确定性）
```csharp
double PredictRaw(GbdtModel m, double[] x) {
    double s = m.baseScore;
    foreach (var t in m.trees) {                 // 固定树序串行累加（00 §6.3 规则 5）
        int i = 0;
        while (t.feature[i] >= 0) i = (x[t.feature[i]] <= t.thresholdOrLeaf[i]) ? t.left[i] : t.right[i];
        s += t.thresholdOrLeaf[i];
    }
    return s;
}
double Predict(GbdtModel m, double[] x) {
    double r = PredictRaw(m, x);
    double y = m.isLogistic ? 1.0 / (1.0 + DMath.Exp(-r)) : r;
    return Math.Clamp(y, m.clampMin, m.clampMax);
}
```
- 只用比较、加法和 `DMath.Exp` → 跨机器逐位一致（00 G-20）。
- 预算：单次 `Predict`（7 个输出 × ≤ 400 棵树 × 深度 ≤ 6）≈ 17k 次比较，约 20–50 μs；`EstimateEdge` 三档 ≈ 0.15 ms。每小时 AI 调用上限 `ProxyCallsPerHourCap`（超出时按候选优先级截断，**截断规则固定**，不看耗时）。

#### 4.6.7 `EvaluatePlan`（返回 11 的 `PlanAssessment`）
```text

  for each 目标格 T_i：
     attackers = committed 编组中的机动营（真值），按“剩余比例” rem 缩放（初始 1）
     defenders = T_i 内敌估计 + ReinforceFactor × T_i 的敌控邻格敌估计
     y = Predict(BuildFeatures(attackers × rem, defenders, 最佳边))
     p3 = y[PCapture72h]
     P_i = 1 − (1 − p3)^(avail / 3)                    // 72h = 3 天的易手概率外推到可用天数
     successP ×= P_i
     T_hat = (p3 ≥ 0.05) ? y[HoursToCapture] / 24 + 3 × (1 − p3) : D     // 期望用时（天），保守加上未易手的等待
     avail = max(0, avail − T_hat)；days += T_hat
     lossFrac = y[AttLossFrac24h] × min(T_hat, 3)；rem *= (1 − lossFrac)
     killed += lossFrac × attackersPersonnel × KilledShareOfLosses
     equipLost += y[AttVehLossFrac24h] × min(T_hat, 3) × attackersVehicles
mid 档给出 successP、expectedKilled（round）、expectedDays（ceil）、expectedEquipmentLost（round）
successPHalfWidth = |P_low − P_high| / 2
```
- 解释：用 72h 易手概率作“每 3 天的独立尝试”外推（几何近似），够用且可手算；目标格依次攻取。

#### 4.6.8 `StandardScenario(country, rival)`
```text
想定：rival 沿全部接触边进攻 14 天（✅ 11 §4.13）
对每个本国前线格 t（H3 升序）：
   attackers = rival 情报估计中位于 t 敌方邻格的营（按边数平分）；defenders = t 内本国营（真值）

```

## 7. 边界情况

| 情况 | 处理 |
|---|---|
| 编组没有机动营（只剩支援营） | 防守分配中所有营为 `TileReserve`；编组 Attack 任务 → 分解失败，父命令 `Failed`（09 通知“无可用机动营”） |
| 地块内只有 1–2 个机动营 | R = 0；1 个营时分配到威胁最大的边；全部边无威胁 → `TileReserve` |
| 所有边威胁都低于 `CoverThreatMin` | 全部 `TileReserve`；战斗开始时 09 §4.6.2 第 2 条自动选人 |
| 情报画面为空（无任何敌情） | Threat = 0；OperationalAi 姿态多为 Hold/Defensive。轴线候选的敌格若无任何估计，按 `PriorCpL1` 当作一个未知营处理（不当作空格），避免 AI 对“看不见”的地块盲目冒进 |
| 敌估计 CP = 0 导致除零 | 所有比值分母取 `max(0.05, x)`（CP）或 `max(1e-6, x)`（能力分量） |
| `StripSituationView` 中无可用连 | 返回空指令列表 |
| 轮换候选与预备队投入争同一个连 | R2 先执行；被 R2 选中的连在 R3 中不可再选（局部副本中已改角色） |
| 炮兵连数为 0 | R4 不输出 |
| 两个轴线的 assigned 旅重叠 | 轴线选择时旅只分给第一条轴线；后续轴线兵力不足则 ratio 低，可能降为 Shaping |
| 代理模型文件缺失或特征名不匹配 | 加载失败 → 回退到“兵力比启发式”：`p3 = clamp((ratio − 1) / 4, 0, 0.95) × (1 − 0.5 × fort)`，并在界面警告；不允许静默使用错误模型 |
| AI 国家预算为 0 或负 | 采购跳过；不调用 SetAllocation 以外的花钱接口 |
| 战争中 AI 失去全部前线 | stance = Defensive；无前线 → 无轴线候选 |
| 停火期间 | stance = Hold；不产生跨越停火线的 Move（11 会拒绝） |
| 同一刻 AI 与玩家抢同一二手批次 | 11 规则：按（提交时刻，CountryId）先到先得 |
| `Historical` 指令目标已不可行（地块已被占） | 指令中跳过已占地块；全部已占 → 指令失效，转 Plausible 逻辑 |
| 难度在游戏中被修改 | 作为模拟输入记录（15 输入日志），下一次重规划生效 |

## 8. 测试用例

**T1 效用曲线与否决**
曲线 `(0.2,0)(0.8,1)`：`Eval(0.5) = 0.5`；`Eval(0.1) = 0`；`Eval(0.9) = 1`。考量：c1（w=2，x=0.5 → 0.5）、c2（w=1，曲线 (0,0)(1,1)，x=0.8 → 0.8）、c3 否决（x 使曲线为 1）。期望 U = (2×0.5 + 1×0.8)/3 = 0.6。若 c3 输出 0 → U = 0。

**T2 影响力传播**

期望 Threat：D 2.0、C 1.0、B 0.5、A 0.25；若再有一格 E 与 A 相邻（距 D 4 跳）→ 0。

**T3 名额分配**
a) A = 4，威胁 [3.0, 1.0]（第三条 0.2 < 0.25 被排除）→ 先各 1，余 2：份额 [1.5, 0.5] → floor [1, 0]，余 1 按余数 [0.5, 0.5] 平局取 i 小者 → [3, 1]。
b) A = 3，威胁 [5.0, 0.5] → 先各 1，余 1：份额 [0.909, 0.091] → floor [0,0]，余 1 给 i=0 → [2, 1]。
c) A = 1，威胁 [2, 1, 1] → [1, 0, 0]。

**T4 轮换（soviet 预设）**
一线连 c1：CS 0.42，疲劳 0.3，x = 5 000，上次轮换 90 min 前。候选：c2（二梯队，CS 0.80，疲劳 0.30，x = 7 000）；c3（预备，CS 0.90，疲劳 0.55，x = 5 200）。

**T5 GBDT 推理（手算）**
一棵树：节点 0：`f2 ≤ 0.5` → 左=节点 1（叶 0.3），右=节点 2；节点 2：`f0 ≤ 10` → 左=节点 3（叶 −0.2），右=节点 4（叶 0.8）。`baseScore = 0.1`，logistic。
输入 x[0] = 12，x[2] = 0.7 → 右、右 → raw = 0.9 → p = 1/(1+e^−0.9) = **0.71095**（±1e-5）。x[2] = 0.5（边界，≤ 走左）→ raw = 0.4 → p = 0.59869。

**T6 EvaluatePlan（单目标格）**
mid 档：`p3 = 0.5`，`HoursToCapture = 36`，`MaxPlanDays = 9`。
期望：`P = 1 − 0.5^(9/3) = 0.875`；`T_hat = 36/24 + 3 × 0.5 = 3.0` 天；expectedDays = 3。low 档 p3 = 0.7 → P = 1 − 0.3³ = 0.973；high 档 p3 = 0.3 → P = 1 − 0.7³ = 0.657；halfWidth = (0.973 − 0.657)/2 = 0.158。11 显示 “87.5% ± 15.8%”。

**T7 滞回**
当前方案 U_cur = 10.0；新方案 U_new = 11.5（+15%）→ 不调整（< 20%），界面显示“收益 +15% < 20%”。U_new = 12.5（+25%）→ 调整；其中某营 lastChangeTick 在 70 分钟前 → 该营不动（< 120），其他营照常调整。

**T8 采购评分**
AZE，2016 年，类别 uav_male（priority 1.0，ThreatMatch 1.0）：候选 X（origin TUR 位次 0 → 1.2；approvalP 0.8；DirectPurchase vulnerability 1.0，dependencyAversion 0.3 → 0.7；value 10；单价 5 + 年维护 0.5 × 5 年 = 7.5）→ score = 1.0 × 10 × 1.2 × 0.8 × 0.7 / 7.5 = **0.896**。候选 Y（origin ISR 位次 1 → 1.1；approvalP 0.9；value 12；单价 8，维护 0.8 → 12）→ score = 12 × 1.1 × 0.9 × 0.7 / 12 = **0.693**。期望先选 X。

**T9 确定性**
同一存档运行 48 游戏小时：(a) trace 开 vs 关；(b) 模拟线程数 1 vs 8；(c) AI 国家列表在内存中的插入顺序打乱。期望三组的每小时状态哈希（15）完全相同。

**T10 R4 炮兵分配（western）**
|B| = 5，有活跃片段 → nDS_min = ceil(5 × 0.4) = 2。openRequests 1 个；敌炮兵目标 2 个（L4、L3）；cbAreaFireAllowed = false。
